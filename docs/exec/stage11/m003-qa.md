## Findings

- **QA-M003-001 (Medium, TKT-27 / TSK-27.5 test tooling; doc accuracy).**
  - **The defect.** `tests/deploy/drill/restore-drill.sh` fails at 37efa1e. Its `start_app` passes `BETTER_AUTH_URL`/`PUBLIC_BASE_URL=http://localhost:<port>` to the production image. Since DES-219 (0d3e077) and the EXE55 entrypoint config check (61fcb8d), the container exits 1 with `config.invalid: BETTER_AUTH_URL, PUBLIC_BASE_URL`, and the script stops at "app udgam-drill-a not healthy". The drill was written on the TKT-27 branch (16a1ab5) before those changes merged. No CI or `pnpm test` path runs it, so the integration merge did not catch the break.
  - **The stale record.** `docs/ops/deploy.md` "Verification record → Done locally" says "The backup and restore drill passes". That record is stale for HEAD.
  - **Verified fix.** Use `https://localhost:$2` for both URLs; curl still reaches `http://127.0.0.1:<port>`. With that change the drill PASSes (E20).
  - **Smaller items in the same script.** `start_app` should print `docker logs --tail` on failure (it currently hides the cause). The ports (4703/4704) and the `udgam-app:current` tag are hard-coded.
- **QA-M003-002 (Low, process).** `docs/exec/ledger.md` has no M-003 entries at 37efa1e: no per-task rows for TASK-28/29/30 and none of the "BLOCKED (owner precondition)" rows that EXE52 says the ledger carries. `HANDOFF.md` is still the Stage 10 version. Both must be written at this gate (CLAUDE.md: update the ledger after each phase; rewrite HANDOFF at the end of the stage).
- **QA-M003-003 (Info, doc drift).**
  - `docs/ops/deploy.md`'s local record gives `check-standalone` as 60.7 MB; at HEAD it is 65.2 MB (still within the 150 MB budget).
  - The same record says "the forged-header test … passes", which this QA run confirmed independently, including a pass-through negative control.
  - The capture 32 MB and attestation 11 MiB caps are covered only by `caddy adapt`, not by a live cap+1 request. Optional: add both to the `it.each` in `forged-header.stack.test.ts`.
- **QA-M003-004 (Info, coverage).** None of the Docker-dependent checks (`forged-header.stack`, `entrypoint-config.stack`, the restore drill and the bootstrap run) runs in CI or in `pnpm test`; the 7 skipped tests are these. QA-M003-001 is the direct result. Consider a single `tests/deploy/run-local.sh` (or a CI job with Docker) that builds the image once and runs all four, so an integration merge re-proves them.
