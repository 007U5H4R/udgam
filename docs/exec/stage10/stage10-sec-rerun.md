## Part 2 — new problems in `9918ab1..b13dfaf`

**No new finding issued.** Checked:

- **Multipart pre-scan (`read-form.ts`) — bypass:** undici's parser (Node 22.22.2) locates the bare boundary and then requires `\r\n--` before it, else fails; so its part sequence is exactly the `\r\n--boundary` sequence the pre-scan counts, and the count can only diverge if the two extract different boundary *strings*. `p5-boundary-diff.ts` compared 30 Content-Type shapes (duplicate params, quoted/unquoted, case, whitespace around `=`, trailing junk after a quoted string, unterminated quote, non-ASCII, 70/71 chars, folded header): 24 agree; the 6 that differ all fail closed — the pre-scan accepts but undici fails (`boundary = x`, `boundary= x`), the pre-scan refuses (`"x"junk`, `"x` unterminated), or the encodings differ (`xxxxé`: latin1 vs UTF-8, so no body satisfies both opening delimiters → `bad_form`, parser not called). Header-block cap (2 KiB), field cap (16 KiB) and the search cutoff one past 7 delimiters hold on a 30 MB single header line (31 ms). File parts stay unbounded by design (one copy, ≤ 30 MB, ~90 ms; base64 221 ms). **Legit refusal:** the real Chromium client passes (e2e 16/16 incl. "photos go with Send" when staging is unavailable); the shape tests in `read-form.test.ts` cover the quoted boundary.
- **EVM sender (`sender.ts`) — deadlock / leak / order:** per-key FIFO via promise chaining; queue entries deleted when the tail is current (no leak on success or failure); re-entrancy via AsyncLocalStorage so `fund`'s approve→fund holds the buyer key without self-deadlock; no nested cross-key acquisition anywhere in `chain.ts`/`client.ts` (operator sends never run inside a buyer `exclusive`, and vice versa), so no lock-order cycle; the queue is held only prepare→broadcast (RPC timeout 10 s) except in `fund` (bounded by the 30 s receipt timeout); `receiptOf` resets the nonce on a failed wait and viem's manager re-reads `pending`, so a dropped tx leaves no gap. State lives on `globalThis` under `Symbol.for`, shared across Turbopack runtimes. Tests cover order, retry-once, per-chain keys. **Observation (not a finding):** `isNonceCollision` also matches "transaction already imported"/"already known", which Anvil returns when the *same* signed tx is broadcast twice (`p6`: a duplicate raw broadcast answers `transaction already imported`); a retry would then send a second tx for one intent. Unreachable in the app: both transports use `retryCount: 0` and undici never retries a POST, so an identical re-broadcast cannot occur. Worth a comment, not a change.
- **Redirect rules (gfw/sentinel):** `new URL(location, from)` resolves relative Locations against the current hop; origin compared as scheme+host+port against the base URL's (GFW) or the request's own (Sentinel), so protocol-relative, host-suffix, scheme-downgrade, port and userinfo forms are refused; the Location is never logged (`redirect_refused` logs status and hop only); 303 and 301/302-after-POST become bodiless GETs as Fetch would; body is a string so a 307/308 re-send works; max 3 hops; `res.url` of the final hop still yields the resolved dataset version. Verified by `redirect-variants.mts`.
- **HSTS gate on localhost:** decided at build time by `testSurfacesOn` (`NODE_ENV !== 'production' || E2E === '1'`). Playwright builds with `E2E=1` → no HSTS (manifest checked, `csp.spec` asserts it). A plain `pnpm build && pnpm start` on a developer machine does bake HSTS onto `http://localhost`, but browsers ignore HSTS on non-secure (or cert-error) origins, so nothing sticks. No harm.
- **gitleaks allowlists:** the `private-jwk` allowlist hides exactly two things in the tree (scan with the allowlists removed: `evals/fixtures/crypto-vectors.json:211` = the published `testOnlyPrivateJwk`, and `docs/proof-feed.vectors.json:18008` = the negative vector whose `d` is 43 `A`s, an unusable zero scalar). The regex allowlist matches only `"d":"A{43}"` exactly, and a real key in the same file as a zero key is still reported (`mixed.json`). `[extend] useDefault = true` unchanged; nothing disabled.
- **SHA pins / workflows:** see SEC-202 above; `permissions: contents: read` unchanged; no `pull_request_target`.
- **Test helpers (`tests/helpers/tmp.ts`):** `tempDirs()` registers `afterAll` at `tests/helpers/db.ts` module top level, so importing `db.ts` outside vitest now throws (`Vitest failed to find the current suite`). The only non-test importer is `evals/harness/m2/settlement.ts`, which nothing outside `*.evm.test.ts` imports, and `pnpm eval` (`evals/harness/run.ts`) does not reach it. No runtime or gate impact; noted for the maintainers.
- **`limits.ts` memory:** 8 × 30 MB bodies held about three times over (chunks + `Buffer.concat` + parsed File) ≈ 720 MB peak plus 8 × 10 MB stage bodies — within EXE50's "under 1 GB" on the 12 GB host.
- **Capture `in-flight`/`staging` changes:** counts only; refusal order (agent cap before global) unchanged; slot release idempotent.
