- **Commit:** `dd7b0c1` (branch `build/stage7`), reviewed in a shared clone at `<scratchpad>/s10-auth-capture` (read-only on source).
- **Scope:** auth and session (`src/lib/auth`, `src/app/_auth`, `src/app/api/auth`, `(public)/sign-in`, `src/proxy.ts`, `src/lib/security`, `client-ip`, `rate-limit`, `request-id`); enrolment and devices (`src/lib/enrolment`, `src/app/api/enrol`, `(agent)/enrol`, `(admin)/admin/phones/actions.ts`); field capture (`src/lib/capture`, `src/app/api/capture` and `/stage`, `src/lib/media`, `src/app/api/media`, `src/app/api/telemetry`); the `(agent)` layout, pages and the one `(agent)` Server Action; `src/lib/config`.

## Method
1. Read every non-test file in scope (about 5,100 lines) plus the modules they lean on (`src/lib/crypto/ecdsa.ts`, `key-file.ts`, `src/lib/log.ts`, `src/lib/db/client.ts`, `src/lib/certificate/telemetry.ts`, `src/lib/db/queries/{field-home,picking-detail}.ts`, `scripts/seed-accounts.ts`, `next.config.ts`, `tests/guard-coverage.test.ts`), and `technical-plan.md` §10, §16, §17, TSK-27.3, `decisions.md` EXE14.
2. Walked the threat checklist per component, tracing each request path from the route handler or action to the write.
3. Checked framework behaviour in the installed packages rather than from memory: Next 16.3.6 Server Action origin check (`node_modules/next/dist/server/app-render/action-handler.js:436-466`) and body handling (`:518-640`).
4. Ran three probes with `tsx` against the clone's source (`<scratchpad>/probes/p1-clientip.ts`, `p2-slots.ts`, `p3-parsecost.ts`), using the main checkout's `node_modules` through a temporary symlink (removed afterwards). No server was started; no `pnpm install`, no `.next`, `.e2e-data` or `test-results` were created.

## Checked, no issue (per checklist item)

- **authn/authz, roles, IDOR, cross-org:** `readSession` fails closed on an unknown role or empty org (`session.ts:26-31`); `authorize` 401/403; every in-scope page, action and handler calls `requireSession` first (`layout.tsx:14`, `enrol/page.tsx:14`, `record/page.tsx:17`, `pickings/[eventId]/page.tsx:51`, `(list)/page.tsx:32`, `home.tsx` via its callers, `language.ts:17`, `enrol/route.ts:26`, `capture/route.ts:50`, `stage/route.ts:53`, `thumb/route.ts:23`, phones actions `:24,37,50,63`); org and agent scoping is in SQL (`org-scope.ts`, `assign.ts:21-35`, `codes.ts:37-44`, `enrol.ts:131-137`, `phones.ts`, `picking-detail.ts:44`, `field-home.ts:32,50,57`, `media/access.ts:14-25`); the thumbnail is served only to the owning agent or an admin of the plot's org, never to buyer/processor, and a foreign id is a 404. Proxy redirects only; it never decides access.
- **session, cookie, CSRF:** session cookie `httpOnly`, `sameSite=lax`, `secure` in production (`auth.ts:98-101`); only `GET get-session` and `POST sign-out` of Better Auth are reachable over HTTP (`[...all]/route.ts:15-18`), so `role`/`orgId` (`input: false`) and sign-up are unreachable; sign-in runs in-process behind the atomic three-key reservation (`sign-in-limit.ts:52-73`: one `writeTx` reads then `hit`s, refund only on success or a non-credential refusal, so neither a parallel burst nor a crafted refusal buys extra guesses); Server Actions are protected by Next's Origin/Host check (`action-handler.js:436-466`, verified in the installed 16.3.6) and the `(agent)` route handlers by `sameSite=lax` (a cross-site POST carries no cookie; the attribute is explicit, so Chrome's 2-minute Lax+POST exception does not apply). No open redirect: the post-sign-in target comes from `HOME[role]`.
- **input validation / SQL:** zod `strictObject` for the payload (`payload.ts`), telemetry (`telemetry.ts:28-31`) and env; the enrol body is shape-checked and the JWK limited to exactly `{kty,crv,x,y}` with 43-char base64url coordinates, imported and re-exported before thumbprinting (`enrol.ts:49-60`); every raw `sql` template in scope interpolates column references only (`sign-in-limit.ts:81`, `codes.ts:108`, `rate-limit.ts:35,80`, `phones.ts:26`); no command execution from input.
- **file upload:** Content-Length required and capped before the body is read on capture, stage, enrol and telemetry; body streams are cancelled at the cap and at a deadline (`read-form.ts:32-62`); photos are sniffed (JPEG / HEIC with AVIF refused, whole `ftyp` box read, `sniff.ts`) and the signed MIME must match the bytes; sizes and SHA-256 are re-checked against the signed payload (`boundary.ts:141-148`); staged bytes are re-hashed on use and a tampered copy is discarded (`staging.ts:301-314`); thumbnails are re-encoded (EXIF stripped) with `limitInputPixels` 50 MP, 2 concurrent decodes and a cached placeholder (`thumbs.ts:46-52, 64-77`); EXIF make/model are stripped of control and format characters and capped at 64 code points (`exif.ts:60-64`), GPS is range-checked; originals are never served.
- **path traversal / DATA_DIR:** media, thumbnail and staging paths are built from hex SHA-256 and `[A-Za-z0-9_-]` segments and re-checked to be inside the store (`store.ts:40,68-77`, `thumbs.ts:54-59`, `staging.ts:99-119`); the only client-supplied path-like input is the staged hash (`SHA` regex); user key files use `USER_ID` `^[A-Za-z0-9_-]{1,128}$` (`signing-keys.ts:26-32`); every root goes through `runtimePath`.
- **SSRF:** no `fetch` in scope (remote sensing is another area).
- **XSS / CSP:** no `dangerouslySetInnerHTML` or `innerHTML` in scope; per-request nonce + `'strict-dynamic'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, tile host on `/admin` documents only; `'unsafe-eval'` only when `NODE_ENV=development`; the proxy overwrites any client-sent `x-nonce` (`proxy.ts:39-40`); `'unsafe-inline'` for styles is a recorded decision (TASK-20 EXE candidate 4).
- **data exposure:** capture refusals name a reason and a zod path only; `authErrorResponse` carries no detail; `/api/auth/get-session` is per-cookie; the thumbnail answers 404 for anything not readable; telemetry logs the three validated members only.
- **rate limits, replay, idempotency:** fixed windows under `writeTx` (`rate-limit.ts:30-54`), opportunistic sweep; enrolment 5 per code for life + 10 per address per hour, unknown codes limited by hash (`codes.ts:101-115`); capture per address and per (agent, claimed device) so a public device id cannot lock another agent out; idempotent replay only for an accepted payload and only after the signature and device-ownership checks (`pipeline.ts:344-355`), re-checked under the write lock with the unique-violation fallback.
- **keys and signatures:** ECDSA P-256 / SHA-256, P1363 only, 64-byte check, `verify` never throws (`ecdsa.ts:52-61`); the canonical-bytes check precedes the signature so two encodings cannot both verify (`boundary.ts:87-100`); server-held keys are created `wx` 0600 via `link()` in a 0700 directory and tightened on load (`key-file.ts:61-103`); the device private key is non-extractable in the browser and only the public JWK is posted (`EnrolClient.tsx:102-106`); a revoked key cannot be re-enrolled (`enrol.ts:107-108`).
- **error and log leakage:** `errFields` logs class and driver code only; pino redaction covers every `SECRET_ENV_NAMES` entry, `cookie`, `authorization`, `signature`, `password`, `key` at the top level and one level down; `loadEnv` errors name variables and rule codes only (tested); the dev auth secret is logged by event name only.
- **config defaults:** production requires `BETTER_AUTH_SECRET` (≥ 32) and the live provider; `E2E=1` is the single gate for test surfaces (`test-surfaces.ts`, enforced by the "one rule" test) and `/__test__` answers 404 without it; `SEED_PASSWORD` is required unless `NODE_ENV` is explicitly `development`/`test` (`seed-accounts.ts:54-59`); `env` is a non-enumerable, read-only proxy. The 3 MB Server Action limit is SEC-005.
- **privilege escalation via enrolment:** a code redeems only for the signed-in agent it was issued to (`codes.ts:118`, `enrol.ts:110`), issued/assigned/revoked only by an admin of the same org, key thumbprints are unique, `/api/enrol` needs the agent role. SEC-001 is the one path around these boundaries.
- **dependencies:** no new runtime dependency in this area beyond the pinned set (`better-auth 1.7.6`, `sharp 0.35.5`, `exifr 7.1.3`, `zod 4.6.5`, `next 16.3.6`); CI's `pnpm audit --prod` is the gate.
